# Chat Subagent suite v2

本套件版本与运行时 policy v4 相互独立。v1 题面、标注、结果不覆盖。

## 组成与标注

- 8 道未改写的简单回归题，保留原题和原期望一起冻结。
- 8 道新查证题：6 道包含三条独立证据支线，2 道要求按顺序合成一个结论。
- 8 道新审计题：事实冲突、角色误信、证据不足、兼容因果、跨时点变化、指定修复和干净案例。
- 16 份新卷宗各有 51～81 个 Schema 合法对象，至少三分之二为可检索的历史批次；
  每个批次有事件、观测与交接记录，包含相近名称和不同时间，测试范围筛选。
- 预先标注 10 道 parallel_eligible，另 6 道复杂题不以提高委派率为目标。
  此标注用于分层报告，不作为传给模型的指令或正确性门槛。

`specification.json` 为人工编写的题面、原始证据和判定依据；`suite.json` 为物化的完整冻结
输入、期望、参考候选和标注。生成器在 `benchmark/chat_subagent_suite_v2.py`，拒绝覆盖已有冻结文件。
模型只接收 CaseFile、题面和焦点；参考答案、判定依据和可委派标签不传给模型。

## 评分契约

只读题明确禁止补丁，评分要求零建议。audit-07 明确给定权威来源和唯一可改字段，才要求补丁。
审计题明确仅把世界事实冲突写为 finding；认知差异、信息不足和相容解释只在答案中说明。
事实冲突需要同一对象、同一时刻、同一事实层级的互斥断言；不同时间或认知层级不能混淆。
题面要求按 A/B/C 逐项归类，评分逐项检查标签和必要原文引用，不能靠只提到正确关键词通过。
评分器保留原引用合法性、权限与补丁可执行性检查；不会因为改了题面而继承无关旧期望。

校准先验证 24 个参考候选全部通过，再验证错误分类、删引用、把误信判冲突、漏掉明确要求的
修复等负例均失败。paid run 入口在任何模型调用之前执行校准并写入 calibration.json。
本套件没有额外调用 LLM Judge；标签检查是受控任务判定，不宣称对自由叙述做了完整语义审核。

## 重跑与结果边界

在 backend 目录：

```powershell
uv run python -m casefile.benchmark.chat_subagent_v4_parallel `
  --suite-version v2 --output-dir var/benchmark/v4-suite-v2-UNIQUE --budget-cny 18
```

3 个独立进程，共 24 题 × 3 次 = 72 次。保存最终候选用于人工复核，并冻结源码、题集与 Skill 哈希。
同时报告全体通过、非空答复完成、分类正确、必要引用、误报、子任务完成、可委派题中的委派率、
token 和延迟。缺少规定汇总格式时单独识别，不把所有格式失败说成事实错误。
v2 成绩不得与 v1 直接计算质量提升，也不据单组运行证明 subagent 胜过单 Agent。
它是合成的有界检索/推理工程基准，不代表自然创作大卷宗的全部复杂性。
