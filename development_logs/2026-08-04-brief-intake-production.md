# Brief Intake 生产闭环实施日志

日期：2026-08-04
状态：完成，待用户视觉审阅
范围：仅实现建案中心 A「我有一个想法」生产闭环。

## 目标

将真实产品流程升级为可由服务端恢复的完整闭环：

`最初想法 -> 关键追问 -> 创作简报确认 -> /brief 正式审阅`

原始输入持续保存为不可变 `SourceRecord`。Agent 仅生成问题或不可变候选，不直接覆盖用户内容；采用候选只投影为可继续正式审阅的 Brief 草稿，不在建案中心冻结 BriefVersion。

## 已确认边界

- 新增独立 `BriefIntake` 聚合，不把问题、回答过程或字段来源塞进最终 Brief。
- 使用三张 BIGINT Identity 表：`brief_intakes`、`brief_intake_questions`、`brief_intake_candidates`。
- Intake 所有写入使用 `expected_intake_revision`；采用同时校验 `expected_brief_revision`。
- 候选正文、输入哈希和父子谱系不可修改；历史候选不删除；“保存”为可变书签元数据。
- 问题最多两道、硬问题最多一道；可选问题可进入待决定队列，硬问题不可挂起。
- Agent 不可用或失败时允许用户创建人工候选继续，不生成本地伪 Agent 结果。
- 对话修改只支持单轮指令，并从当前候选生成子候选。
- 采用候选后跳转 `/brief`；原子 anchors/constraints 仍由正式审阅页确认。
- B-D 只保持“规划中”；不引入 Workspace、Membership 或团队协作。
- 现有未提交工作全部视为用户资产：不重置、不覆盖、不提交、不推送。

## 2026-08-05 Agent 润色增强

目标：让作者能在任务开始前选择润色强度，并在任务完成后明确看到“未修改”、逐字差异、任务摘要和叙事增强新增细节；继续坚持原稿不可覆盖和人工采用边界。

确认范围：

- 三档模式固定为 `proofread`、`rewrite`、`narrative_enhance`，默认使用表达优化。
- 模式冻结在 TaskRun `input_jsonb`，不新增数据库列；结果回写模式和 `introduced_details`，支持刷新后恢复审阅语义。
- 非叙事增强模式只要报告新增细节即拒绝结果；叙事增强允许少量推测性扩写，但必须逐项展示给作者。
- 差异由前端对冻结原稿与 Agent 原始候选确定性计算；作者随后对工作稿的手工编辑不冒充 Agent 修改。
- 旧的成功润色任务缺少新增字段时按“表达优化、无新增细节”兼容显示。
