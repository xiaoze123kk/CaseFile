---
name: evidence-driven-delegation
description: 对复杂只读问题进行有界分工，并用原始证据复核子任务结论。
---

先判断用户问题能否拆成独立的局部查证，不按关键词自动生成时间线或角色任务。
收到的原始对象是定位锚点，不要求父 Agent 预先读完答案。需要比较多个来源、
核对相互独立的约束或排查多条解释时，优先将独立的证据缺口交给子 Agent。
每项任务明确：一个具体问题、1 至 3 个已定位对象、尚缺的证据、完成标准。
任务最多两项，不得重复回答整个用户问题，不得把存在先后依赖的问题并行分配。
若单次读取即可解决、任务不可独立或涉及写操作，选择 single 并说明原因。
初始记录未覆盖目标不代表卷宗没有目标，也不代表任务不适合委派。
先检查题目明确指定的 ID 和 focus；缺失时用可用的按 ID 读取工具补定位。
只有实际查询不存在或读取预算用尽仍无法定位，才以定位不足选择 single，说明缺失对象。
object_ids 是真实存在的锚点 ID，不是问题名、集合名或自行生成的 ID。
已提供原文不代表已完成比较：两组证词都可见，但各自与事件时间的对应尚未核实，
可以按两组独立核对分工；若只是问一条记录的标题，直接 single。
每项任务还需 scope 和 independence_reason，说明局部范围以及为何不依赖另一子任务。
收到 validation_feedback 时按字段或未知 ID 修正一次，不重复提交原计划，不把格式失败当成任务不可拆分。

子任务只能检查锚点及一跳直接引用范围；范围内可自行读取补证据。
范围不足时返回 partial 和具体未覆盖项，不继续全卷宗搜索，不把未发现解释成不存在。
收尾必须区分已核实事实、推断、疑点和信息不足，事实和确认冲突必须绑定原始对象 ID。
已完整检查局部问题且未发现冲突，也可以完成；不能为了输出 finding 制造问题。

父 Agent 收到结果后，逐项核对附带的原始 source_records，必要时重新读取。
子任务 completed 只表示局部查证结束，不代表结论已经正确。
最终引用来自原始记录，不能引用子任务摘要。疑点和未知项不得升级为确认冲突。
不满足证据要求的子任务结论应丢弃或标为未验证；继续完成有证据支持的用户请求。
