# CaseFile 数据库迁移职责说明

本目录维护 PostgreSQL 18 的个人版数据库结构。Alembic migration 是结构事实来源，`backend/src/casefile/data_postgres/models/` 的 SQLAlchemy metadata 必须与唯一 head 一致。

## 当前六段基线

```text
V20260726131010  users + projects
        ↓
V20260726131012  casefiles + drafts + casefile_objects + casefile_refs + draft_operations
        ↓
V20260726131014  entities + people + locations + events + information_units
                 + evidence_items + testimonies
        ↓
V20260726131017  narrative_phases + claims + hypotheses + reasoning_paths
                 + reasoning_nodes + reasoning_edges + resolution_specs
                 + resolution_slots + casefile_constraints + knowledge_states
                 + knowledge_state_entries
        ↓
V20260726131019  draft_snapshots + canon_versions + audit_events
                 + 循环外键 + 基线数据库函数与触发器
        ↓
V20260728084832  CaseFile v1 字段扩展 + relationships + structure_locks
                 + casefile_contract_refs + user_provider_settings
                 + briefs + brief_versions + task_runs + task_attempts + task_events
```

最终恰好 37 张业务表。所有主键为 `BIGINT GENERATED BY DEFAULT AS IDENTITY`，关系外键均为 `BIGINT`；不使用 UUID 主键。CaseFile v1 的稳定字符串 ID 只保存在契约对象字段中；`briefs.public_id`、`casefiles.object_id` 和 `drafts.version_id` 是契约所需稳定 ID，不是关系主键。

本基线只面向个人产品。不存在 Workspace、Membership、成员、邀请、团队角色、评论、Review Task、共享项目或团队预算的表、列、约束、触发器和种子数据。认证/JWT 尚未实现；当前只存用户级模型 Provider 设置。

## 存储与生成分层

```text
user_provider_settings（用户级密文 API Key 与模型配置）
briefs（可变草稿） → brief_versions（确认后不可变）
                              │
                              ▼
task_runs → task_attempts + task_events（PostgreSQL 队列、尝试与 SSE 回放）
                              │
                              ▼
casefile_objects（稳定身份、契约顺序、来源元数据）
          │ 1:1
          ▼
专用当前态表（规范化字段，Draft 唯一事实源）
          │
          ├── v1 ObjectRef：casefile_contract_refs
          ├── 旧版语义边：casefile_refs
          └── 生成事务：draft_operations + draft_snapshots
                              │
                              ▼
canon_versions（所有者确认的完整不可变 JSON）
          └── audit_events（独立审计，不参与内容哈希）
```

`casefile_objects` 不含通用正文 `payload_jsonb`。JSONB 只承载契约中的结构化叶子、工具/用量/错误摘要、Operation 前后值和完整 Snapshot/Canon；身份、状态、revision、租约及引用使用正式关系列。

CaseFile v1 JSON 顶层为：`casefile`、`resolutions`、`entities`、`relationships`、`locations`、`events`、`information_units`、`claims`、`hypotheses`、`reasoning_paths`、`phases`、`constraints`、`structure_locks`。数据库内部 BIGINT 不替代契约稳定字符串 ID；`casefile_contract_refs` 保存 ObjectRef 的 `object_type + object_id` 及其 JSON Pointer。

## 37 张表的职责、写入方和生命周期

| 表 | 职责与主要关系 | 写入方 | 生命周期 |
|---|---|---|---|
| `users` | 个人账号主体，不含登录凭证。 | 开发种子；未来认证服务。 | 状态可改；被业务引用后不物理删除。 |
| `projects` | 单一 `owner_user_id` 的个人聚合根。 | Project Service。 | 可编辑/归档；所有权不可转移。 |
| `user_provider_settings` | 用户 + Provider 唯一的模型、预算、AES-256-GCM 密文密钥和配置版本。 | Workflow Service。 | 可轮换配置；API 不回显密文或明文。 |
| `briefs` | Project 唯一可变五字段 Brief 草稿及当前确认版本指针。 | Workflow Service。 | revision 乐观更新；当前指针可推进。 |
| `brief_versions` | 用户确认的 Brief 内容、连续版本号与 RFC 8785 哈希。 | Workflow Service。 | 只追加，不可更新/删除。 |
| `casefiles` | Project 唯一 CaseFile，保存 v1 稳定 ID、Schema 和当前 Canon 指针。 | Project/CaseFile Service；Canon 触发器。 | 元数据可改/归档；历史不覆盖。 |
| `drafts` | CaseFile 唯一当前 Draft，保存 v1 版本链字段、Brief 来源、revision 和基准 Canon。 | Draft/Generation Service。 | 单行持续编辑；`locked` 时拒绝 Operation。 |
| `casefile_objects` | v1 对象注册表；稳定 ID、契约顺序、来源、标签、置信度和确认状态。 | Draft/Generation Service。 | 当前态可改；身份/类型不可变，软删除后 ID 不复用。 |
| `casefile_refs` | 兼容旧纵向切片的同 Draft 多值语义边。 | 旧版编辑服务。 | 当前态可重建；已知端点受触发器约束。 |
| `casefile_contract_refs` | v1 ObjectRef 的来源对象、字段 JSON Pointer、目标类型/稳定 ID 与顺序。 | v1 Generation/Projection。 | 随当前 Draft 原子重建；目标由契约 Validator 校验。 |
| `draft_operations` | 有序增量编辑日志和 revision 乐观锁输入；支持 `agent_generate_from_brief`。 | Draft 编辑/Generation 事务。 | 只追加，触发器推进 Draft revision。 |
| `narrative_phases` | v1 Phase 的顺序、发布规则、进入/允许动作/完成条件。 | v1 Generation/Projection。 | 当前 Draft 内可增改；顺序唯一。 |
| `entities` | v1 Person/Organization/Object/System/Faction/Rule Actor 等通用实体字段。 | v1 Generation/Editing。 | 当前态可增改；判别类型不可变。 |
| `relationships` | v1 一等关系对象的标题、类型、方向、真值与可见性。 | v1 Generation/Projection。 | 与 `object_type=relationship` 注册行 1:1。 |
| `people` | 旧版 Person Entity 的 1:1 扩展。 | 旧版 Entity Service。 | 与 Person Entity 同生共存。 |
| `locations` | 同时支持旧版 Location Entity 扩展与 v1 独立 Location 对象。 | v1 Generation/Editing；旧版 Entity Service。 | `entity_id` 与 `object_registry_id` 二选一路径。 |
| `events` | 标题、摘要、v1 时间对象、叙事顺序、阶段、地点、可见性与真值。 | v1 Generation/Editing。 | 当前态可编辑；多值引用进入契约引用表。 |
| `information_units` | v1 信息类型、正文、可靠性、真值、分类、取得条件与发布状态。 | v1 Generation/Projection。 | 当前态可增改；判别类型不可变。 |
| `evidence_items` | 旧版 Evidence 1:1 扩展。 | 旧版 Information Service。 | 与 Evidence Information Unit 同生共存。 |
| `testimonies` | 旧版 Testimony 1:1 扩展。 | 旧版 Information Service。 | 与 Testimony Information Unit 同生共存。 |
| `claims` | v1 Claim 标题、断言、类型、重要度和支持状态。 | v1 Generation/Projection。 | 当前态可编辑。 |
| `hypotheses` | 候选解释、得分和 v1 扩展状态。 | v1 Generation/Projection。 | 当前态可编辑。 |
| `reasoning_paths` | 推理路径、状态、置信度和 `required_for_resolution`。 | v1 Generation/Projection。 | 当前态可编辑；拥有 Node/Edge。 |
| `reasoning_nodes` | Path 内稳定 key、顺序、来源对象和陈述。 | v1 Generation/Projection。 | 随 Path 编辑；key/顺序唯一。 |
| `reasoning_edges` | 同 Path 两个 Node 间的有向论证边。 | v1 Generation/Projection。 | 禁止跨 Path 和自环。 |
| `resolution_specs` | v1 可多条的 Resolution，含标题、结论模式、可接受答案文本与公平性要求。 | v1 Generation/Projection。 | 当前态可编辑；不再限制每 Draft 唯一。 |
| `resolution_slots` | Resolution 内稳定 key、值类型、顺序与动态值。 | v1 Generation/Projection。 | 随 Resolution 编辑；key/顺序唯一。 |
| `casefile_constraints` | v1 约束标题、自然语言陈述、规则表达式及兼容规则 JSON。 | v1 Generation/Projection。 | 当前态可启停和解决冲突。 |
| `structure_locks` | v1 锁对象的强度、字段路径和原因。 | v1 Generation/Projection。 | 与 `object_type=structure_lock` 注册行 1:1。 |
| `knowledge_states` | 旧版 Entity 在 Phase 的总体知识状态。 | Knowledge Service。 | Entity/Phase 组合唯一。 |
| `knowledge_state_entries` | 旧版知识状态内的信息认知、披露和来源。 | Knowledge Service。 | 随 Knowledge State 编辑。 |
| `task_runs` | 一次可租赁生成任务的输入快照、Provider/模型、四类版本、预算、用量、状态和结果。 | Workflow Service；Worker。 | PostgreSQL 队列行；终态保留。 |
| `task_attempts` | 每次领取/恢复执行的候选、Validator 错误、用量和失败摘要。 | Worker。 | 按 Run + attempt_no 只追加。 |
| `task_events` | 可按 sequence 回放的安全阶段、工具摘要、Validator、用量与终态事件。 | Workflow Service；Worker。 | 只追加，不可更新/删除；供 SSE 回放。 |
| `draft_snapshots` | 指定 Draft revision 的完整 v1 JSON、Schema 和 SHA-256。 | Snapshot/Generation Service。 | 每 revision 最多一行；不可更新/删除。 |
| `canon_versions` | 所有者确认的连续正式版本，来源 Snapshot 且保存完整 JSON。 | Canon Service。 | 每次确认追加；不可更新/删除。 |
| `audit_events` | 项目关键动作的 Actor、目标、Trace 和结构化摘要。 | Audit Port；Canon 触发器。 | 只追加；独立于 Canon 内容和哈希。 |

## V20260728084832 字段扩展

- `casefiles` 新增唯一 `object_id`。
- `drafts` 新增 `version_id`、`version_no`、`parent_version_id`、`brief_version_id`、`content_notices_jsonb`、`extensions_jsonb`。
- `casefile_objects` 新增 `contract_ordinal`、`description`、`tags_jsonb`、`created_by_type`、`created_by_id`、`contract_updated_at`，并扩展注册类型。
- `draft_operations.operation_type` 扩为 VARCHAR(64)，加入 `agent_generate_from_brief`。
- `narrative_phases` 新增进入条件、允许动作和完成条件数组；`entities` 新增 aliases/goals/secrets/capabilities 数组并扩展类型。
- `locations` 新增 v1 独立对象路径、名称、访问规则和可见规则；`events` 新增 v1 `time_jsonb` 并扩展真值状态。
- `information_units` 新增可靠性、真值、分类和取得条件；`claims` 新增标题、类型、重要度并扩展状态。
- `hypotheses` 与 `reasoning_paths` 扩展 v1 状态/类型，Path 新增 `required_for_resolution`。
- `resolution_specs` 取消每 Draft 唯一，新增标题、结论模式、可接受答案文本和公平性要求；Slot 新增 `value_type`。
- `casefile_constraints` 新增标题、自然语言陈述和规则表达式。

## 关系与数据库门禁

- Project : CaseFile : 当前 Draft : Brief = 1:1:1:1；Brief : BriefVersion = 1:N。
- 所有当前态专表携带 `project_id + casefile_id + draft_id`，复合外键拒绝跨归属串联。
- v1 一次全量生成要求 Draft 为空，只写一个 `agent_generate_from_brief` Operation 和一个 Snapshot；候选 JSON、Snapshot JSON 与 RFC 8785 哈希必须一致。
- `task_runs` 固化 BriefVersion、输入 Draft revision、Provider/模型配置版本、Schema/Agent/Prompt/Toolset 版本和预算；Worker 通过 `FOR UPDATE SKIP LOCKED` 与 lease 领取。
- `task_attempts` 保留每次候选、结构修复/Validator 错误和用量；`task_events` 只公开阶段、工具摘要、Validator 和用量，不存隐藏思维链。
- Draft Operation 插入锁定 Draft，校验 `base_revision`、连续 `sequence_no`、个人所有者 Actor，并原子推进 revision。
- Snapshot 插入锁定 CaseFile/Draft，要求当前 revision、项目所有者和三层 Schema 一致。
- Canon 插入锁定 CaseFile/Draft，要求来源 Snapshot、内容/哈希、所有者、父版本、连续版本号和四层 Schema 一致；完成后更新两个 Canon 指针并追加 Audit。

### Schema 四层门禁

```text
casefiles.schema_version
  = drafts.schema_version
  = draft_snapshots.schema_version
  = canon_versions.schema_version
```

应用使用 RFC 8785 规范化完整 JSON，对 UTF-8 字节计算 SHA-256。数据库验证 64 位小写十六进制格式，并要求 Canon JSON/哈希与来源 Snapshot 完全相同；数据库不在触发器中组装 Snapshot。

## 触发器分组

| 分组 | 作用 |
|---|---|
| `trg_*_updated_at` | 维护全部可变表的 `updated_at`。 |
| owner/object/discriminator immutable | 禁止项目所有权、对象稳定身份/类型、Entity/Information 判别类型被普通 UPDATE 改写。 |
| `trg_*_registered_type` | 验证核心专表与对象注册类型一致，含 v1 Relationship 与 Structure Lock。 |
| subtype triggers | 同时支持旧 Person/Location 扩展和 v1 独立 Location。 |
| `trg_casefile_refs_known_type` | 验证旧语义引用的已知方向和端点类型。 |
| Operation/Snapshot/Canon gates | 完成 revision、Schema、所有者、内容门禁和 Canon 指针/审计事务。 |
| `trg_*_immutable` | 禁止 `brief_versions`、`task_events`、`draft_operations`、`draft_snapshots`、`canon_versions`、`audit_events` 普通 UPDATE/DELETE。 |

Operation、Attempt、Event、Snapshot 与 Audit 职责不同：Operation 是“Draft 如何变化”；Attempt 是“一次执行发生了什么”；Event 是“可以安全回放给用户的阶段摘要”；Snapshot 是“某个 revision 的完整候选”；Audit 是“谁在何时执行了关键业务动作”。

## 明确延后

本轮不创建登录认证/JWT、邮箱/OAuth、Validator Report、Export Manifest、Patch、Simulation、Compiler、预算账本、删除工作流、Asset、Import、全文/向量投影，以及任何 Workspace、Membership 或团队协作表。
