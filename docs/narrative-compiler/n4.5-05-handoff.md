# N4.5-05 Bounded Full Rewrite 交接

更新时间：2026-09-02

## 结论

N4.5-05 的离线 bounded full-Rewrite runtime 已在当前 `N4.5` 分支完成。实现基于 N4.5-04 Writer development baseline，不使用旧 `scene-repair-patch` 协议：每次 Rewrite 都返回完整 `compiler.scene-render-candidate.v1`，服务端最多生成 `rewrite_1`、`rewrite_2` 两轮，并在初稿及每轮 Rewrite 后使用冻结 `fidelity-only-v1` 复审完整 Checklist。

本阶段只证明协议、lineage、预算和有限状态机闭环可执行，不构成 B2 Rewrite 资格。没有运行 DeepSeek Live、Holdout、B4，也没有接入 Worker、API、PostgreSQL、Quality Critic 或 Polisher。

## 已实现接口

### 领域规范化

`backend/src/casefile/domain/narrative_compiler/prose_checklist.py` 新增 `normalize_scene_rewrite_candidate`：

- 复用 Writer 的严格 candidate 结构、空白段过滤、block ID 和字符门禁。
- Rewrite 1 只接受 `writer/round=0` 直接来源，Rewrite 2 只接受 `rewrite_1/round=1` 直接来源。
- 服务端注入 `stage=rewrite_1|rewrite_2`、`round=1|2`、连续 block identity 和当前完整 Render 的 `previous_render_hash`。
- Checklist 的 `previous_scene_render_hash` 仍表示前一场 accepted Scene，不与本场直接 Rewrite lineage 混用。
- 最终统一调用现有 `validate_scene_render`；公共 Schema 和生成契约未修改。

### Provider-neutral Rewriter

`backend/src/casefile/agent_runtime/prose_rewriter.py` 提供：

- `ProseRewriterRequest/ProviderResult/Execution/Provider`。
- `FakeProseRewriterProvider` 与 `DeepSeekProseRewriterProvider`。
- `build_prose_rewriter_request` 与 `execute_prose_rewriter`。
- 对 ScenePlanIR、NarrativeIR、Profile、Checklist、前一场 accepted Render、当前 Render、Consensus 和 Fidelity Judge Report 的调用前精确复验。
- 对 Fidelity-only Consensus 的确定性重建校验，拒绝伪造的 final verdict、check coverage、report hash、Arbiter 或 policy。
- Provider 视图仅含完整 Checklist/Scene context/Profile、当前 Render、失败/未决 finding 和原来通过的 preservation checks；不含 Gold、Reference prose、私有 task ID 或凭据。
- 输入、Prompt、model、Schema、组件版本、当前 Render、Consensus、Judge report、轮次和预算的 fingerprint；恢复结果必须精确匹配。
- 固定单轮、无工具、`temperature=0`、thinking disabled、SDK retry=0，并区分 `protocol_failed` 与 `inconclusive`。

### Bounded Supervisor

`backend/src/casefile/agent_runtime/prose_rewrite_supervisor.py` 提供 `execute_bounded_prose_rewrite`：

```text
writer render / round 0
  → full fidelity-only review
  → pass: semantic_accepted
  → fail|uncertain: rewrite_1 → full review
  → fail|uncertain: rewrite_2 → full review
  → fail|uncertain: semantic_rejected
```

Supervisor 冻结 Council policy，按实际 Provider 尝试扣减 Scene 调用预算，记录每轮 Render/Council/Rewrite、Rewrite 数和模型调用数。初稿通过时不调用 Rewriter；第二轮后不得第三次 Rewrite、补采样或选择性重试。
