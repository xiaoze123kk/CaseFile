## 已实现接口

### 领域规范化

`backend/src/casefile/domain/narrative_compiler/prose_checklist.py` 新增 `normalize_scene_rewrite_candidate`：

- 复用 Writer 的严格 candidate 结构、空白段过滤、block ID 和字符门禁。
- Rewrite 1 只接受 `writer/round=0` 直接来源，Rewrite 2 只接受 `rewrite_1/round=1` 直接来源。
- 服务端注入 `stage=rewrite_1|rewrite_2`、`round=1|2`、连续 block identity 和当前完整 Render 的 `previous_render_hash`。
- Checklist 的 `previous_scene_render_hash` 仍表示前一场 accepted Scene，不与本场直接 Rewrite lineage 混用。
- 最终统一调用现有 `validate_scene_render`；公共 Schema 和生成契约未修改。

### Provider-neutral Rewriter

`backend/src/casefile/agent_runtime/prose_rewriter.py` 提供：

- `ProseRewriterRequest/ProviderResult/Execution/Provider`。
- `FakeProseRewriterProvider` 与 `DeepSeekProseRewriterProvider`。
- `build_prose_rewriter_request` 与 `execute_prose_rewriter`。
- 对 ScenePlanIR、NarrativeIR、Profile、Checklist、前一场 accepted Render、当前 Render、Consensus 和 Fidelity Judge Report 的调用前精确复验。
- 对 Fidelity-only Consensus 的确定性重建校验，拒绝伪造的 final verdict、check coverage、report hash、Arbiter 或 policy。
- Provider 视图仅含完整 Checklist/Scene context/Profile、当前 Render、失败/未决 finding 和原来通过的 preservation checks；不含 Gold、Reference prose、私有 task ID 或凭据。
- 输入、Prompt、model、Schema、组件版本、当前 Render、Consensus、Judge report、轮次和预算的 fingerprint；恢复结果必须精确匹配。
- 固定单轮、无工具、`temperature=0`、thinking disabled、SDK retry=0，并区分 `protocol_failed` 与 `inconclusive`。

### Bounded Supervisor

`backend/src/casefile/agent_runtime/prose_rewrite_supervisor.py` 提供 `execute_bounded_prose_rewrite`：

```text
writer render / round 0
  → full fidelity-only review
  → pass: semantic_accepted
  → fail|uncertain: rewrite_1 → full review
  → fail|uncertain: rewrite_2 → full review
  → fail|uncertain: semantic_rejected
```

Supervisor 冻结 Council policy，按实际 Provider 尝试扣减 Scene 调用预算，记录每轮 Render/Council/Rewrite、Rewrite 数和模型调用数。初稿通过时不调用 Rewriter；第二轮后不得第三次 Rewrite、补采样或选择性重试。

私有 qualification 包已由 Codex 完成逐题审阅，并由项目所有者明确接受该审定方式。descriptor 冻结为 `review_policy=codex-owner-accepted-review-v1`、`review_status=codex_reviewed`、`qualification_eligible=true`；attestation 同时如实保留 `reviewer_independence=false`，不得表述为独立复审。`QualificationCheck` 会对私有目录边界、8×3 分布、24 题正文/Gold/Consensus/Checklist、证据路径及全部内容与输入 fingerprint 完成严格校验。完整 B2 Live 已通过；该结果只解除 B3 前置门禁，不替代 B3 或 B4，也不授权生产激活。

正式 B2 executor 从每题冻结的坏正文、Fidelity Judge Report 与 Consensus 直接进入 Rewrite 1，不重复调用 Judge 评审已审定的初始输入；每轮 Rewrite 后再以 `fidelity-only-v1` 全量复审，失败时最多进入 Rewrite 2。Runner 固定 `deepseek-v4-pro`、四调用 Scene 预算、24 题分母、clean/stable source 与精确 DeepSeek adapter，并将 source、suite/review、Prompt/component/policy 和门槛纳入 attempt fingerprint。协议或能力失败不补跑；基础设施失败将 attempt 标为 `inconclusive_infrastructure`、停止后续 Provider 调用并以 `not_run` 行保留分母，禁止与后续 attempt 拼接。报告不保存正文、请求 payload、原始响应或凭据，只保存内容 hash、判定、稳定错误码、usage、latency 和脱敏 transport attempt。

`scripts/prose-rewrite-benchmark.ps1 -Mode QualificationLive` 只有在显式传入唯一 `AttemptId`、`-LiveConfirmation RUN_B2_REWRITE_QUALIFICATION_ONCE`，且本地进程环境存在 DeepSeek 凭据时才可启动。确定性预检通过后、首个 Provider 调用前会以不可覆盖的 `attempt-manifest.json` 预占该 ID；已有 manifest 或 `report.json` 均失败关闭，因此中断的 attempt 不能原 ID 续跑。首次正式运行及后续版本处置见下节。

## B2 Live 结果与修复

首次正式 attempt `b2-live-20260902T161117Z` 使用 v1 Rewrite Prompt，报告 hash 为 `2330ac502542bd2f67d75294787dd478ab99c5104ad9fd5d701252683f8bd01e`。结果为 `inconclusive_infrastructure / qualified=false`：14/24 semantic accepted，8 题在 Judge 前因 `compiler_scene_render_length_out_of_bounds` 协议失败，1 题发生 `APITimeoutError`，随后 1 题按冻结规则未运行；新增关键问题和超限 Rewrite 均为 0。报告自哈希有效且不含正文、请求 payload、原始响应或凭据。

8 个系统性协议失败的共同边界是 Profile 要求 300–1200 Unicode 字符，而 v1 只笼统要求“遵守目标字符范围”，没有把精确数值提升为服务端 binding，也没有要求模型在输出前自检；失败调用的 Rewriter 输出 token 为 189–238，且均在 candidate 规范化阶段被拒绝。因为正式报告按策略不保存正文，不能从旧 attempt 事后恢复精确字符数，也不得对旧题选择性补跑。

首次修复版本 `prose-rewriter-v2` / `prose-rewriter-json-object-v2` 新增 `prose-rewriter-length-contract-v1`，但第二次 Live 表明模型仍会贴着 300 字拒绝线生成并因人工估数偏差落到 194–290 字。当前 `prose-rewriter-v3` / `prose-rewriter-json-object-v3` 使用 `prose-rewriter-length-contract-v2`：除精确 `min_chars`/`max_chars` 外，确定性派生 `generation_floor_chars`、block 数及逐 block 最低/目标字符数，使写作目标与硬拒绝线保持安全距离；服务端继续按全部 `blocks[].text` 的 Unicode code point 总数执行原门禁，不放宽 Profile。Fidelity Judge v6 同时增加输出前 Evidence 必填项自审；请求协议 v6 对仍然出现的 required+pass 或 forbidden+fail 空 Evidence 只做保守 `uncertain` 降级，使既有 bounded supervisor 进入第二轮 Rewrite，不把题目提前报废为协议失败。未知、重复或目录外 Evidence 仍失败关闭。资格报告继续只保存 candidate 字符数与 block 数，不保存正文。v1/v2 Prompt 与前两次失败报告保留用于历史回放。

第三次正式 attempt `b2-live-v3-20260903T042158Z` 在 revision `14c55c90d6c0669903a10e55f25126843986677b` 上通过。固定 24 题全部执行并在 Rewrite 1 后被 Fidelity Council 接受：Round 1 rescue `24/24`、Round 2 incremental rescue `0/24`、final rescue `24/24`、preservation `24/24`；新增关键问题、额外 Rewrite、semantic/protocol/infrastructure/not-run failure 均为 0。共 48 次逻辑调用与 48 次物理 transport attempt，候选正文字符数范围 335–673、平均 462.2。source clean/stable、qualification package stable、exact provider adapters 与所有聚合 Gate 均为 true。
