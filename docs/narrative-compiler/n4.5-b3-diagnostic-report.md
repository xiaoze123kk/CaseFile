## 已实现

- 公开 `diagnostic_v1`：24组 Quality、24个 Polisher Scene，八类 focus 各三题；Quality 每类 A/B/tie 各一。保留旧八题集与全部历史资格证据。
- 场景为新编写的诊断上下文，覆盖不同场所的记录核对、未知原因和封存动作；不冒充真实 N4.4 编译产物。当前语义结构集中于该任务族，不能据此推断完整小说场景的泛化能力。
- Gold 为 Codex 非独立审阅，明确标注 authored gold，不冒充 Live Council 或独立人工盲评。只取得开发审阅政策的用户接受，没有把逐题 owner acceptance 预填为完成。
- `DevelopmentLive` 显式入口，默认 Fake 保持兼容；唯一 attempt、严格公开路径/分布/hash/绑定校验，三次独立运行，每次双位置，调用顺序交错。
- 内部不可变配置将 findings 固定为 Flash，Pairwise 分别使用 Flash/Pro；仅显式 Pro 配置允许 Pro Pairwise。默认 v2 指纹兼容；配置变化进入组件输入与请求指纹，跨配置恢复拒绝。
- 沿用完整 Council、Polisher、双位置采用与精确回滚规则。每场冻结一次真实 findings 并保留原始调用来源，复用不制造零成本请求。
- 逐逻辑调用保存脱敏请求、原始响应、transport attempts、真实 usage、未知 usage、解析后组件结果；文件只新建，不覆盖，未落库响应不自动重发。
- 开发允许最多四个独立样本并发，生产逐场串行、默认 Shadow 关闭、Writer/Rewrite/Polisher 活动 Prompt 与模型分工保持不变。
