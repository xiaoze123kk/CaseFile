## 6. 07 要补齐的工程工作

### 6.1 冻结输入与 API

- 增加默认 `false` 的 `prose_renderer_shadow`，贯穿请求校验、输入冻结、持久化与读模型，不只停留在请求 DTO。
- 显式启用只面向 `preview`、DeepSeek、Profile v2，并要求可用且精确匹配的 ScenePlanIR v2/NarrativeIR。Profile v1 和原 N4.4 编译路径保持兼容。
- 前置不满足应在正文 Provider 调用前阻断。按现有冻结协议表达 Shadow 状态，不把 N4.5 失败改写成 N4.4 失败。
- 本阶段只做后端契约及必要的生成物同步，不新增前端页面。

### 6.2 数据库与不可变产物

- 核对现有 Artifact identity/check/unique 约束与仓库写入边界，再同步修改 ORM、迁移和数据库职责文档。沿用已有 Artifact kind。
- Checklist、各阶段 Render、各轮 Judge/Consensus/Arbiter、Preservation、Quality、NovelCandidate 和 CompileManifest 均保留哈希及来源链。
- 使用 ADR 的精确 key 规则；阶段固定为 `writer`、`rewrite_1`、`rewrite_2`、`polished`、`accepted`。同一 CompileRun 的 key 唯一，产物内容不可变。
- 双位置 Pairwise 的两份报告都须可审计，不能相互覆盖；对照现有 Schema/ADR 确认承载方式，不自行丢弃其中一次。
- 每个组件映射到 Step，每次真实调用映射到 Call；持久化原始响应、解析状态、用量、延迟、指纹，并保持作者侧读模型的公开边界。

### 6.3 Worker 串行编排

目标链路为：

```text
冻结的 N4.4 产物
  → Checklist → Writer → Semantic Review
  → 必要时 Rewrite 1/2，各自完整复审
  → Quality findings → Polisher → 完整 Preservation Council
  → 双位置 Quality → 最终接受原稿或润色稿
  → 下一场 → NovelCandidate / CompileManifest
```

- 按 `discourse_order` 串行；下一场只接收前一场最终接受全文及哈希。
- 先复用现有组件的请求、规范化、Evidence 与恢复校验，不重新实现评审规则。
- 语义拒绝、前置阻断或基础设施未决使 Shadow 后续场景停止，不能以未接受正文继续下一场。
- 润色语义失败或质量不稳定时精确回滚原稿，不将回滚视为整场语义拒绝。
- Shadow 默认关闭；不写 Draft、Canon、Exposure，不自动采用正文，不支持 canonical 正文生成。

### 6.4 恢复、取消与并发

- 沿用现有 TaskAttempt lease/fencing；在组件边界检查取消和所有权，旧 Worker 不得继续写入 Step、Call、Artifact 或终态。
- 只有完整 fingerprint 匹配且已持久化的结果才可复用；保留其真实用量和来源，不产生伪造的零成本调用。
- ScenePlan、NarrativeIR、Profile、前一场 accepted Render、Prompt、Schema、模型、policy 或上游产物变化必须使依赖结果失效。
- 覆盖重复 Worker、取消、lease 丢失、组件调用后崩溃、数据库写入失败和重领任务。区分已持久化结果可复用与外部调用结果未落库的未知窗口，不能用跳过审计宣称不重复计费。

## 7. 接手时必须对齐的两个细节

### Council 策略

桌面总图展示完整三角色能力，但当前 Writer/Rewrite 已冻结使用 `fidelity-only-v1`；润色后的 Preservation 使用完整三角色 Council，并按需调用一次 Arbiter。07 不应因为接入完整总图就悄悄更换前半链的策略。运行清单应显式记录每段实际 policy 及其 fingerprint。

### 预算与显式网络重试

ADR 保留最坏 `23/Scene` 硬预算，较少角色的策略节省预算不能用于额外 Rewrite 或采样。当前 Judge 代码还允许对连接错误/超时做一次可审计的显式重试，SDK 隐藏重试仍关闭；Writer、Rewrite、Quality、Polisher 的网络重试为 0。

因此不能简单把“23 次预算”与“所有组件绝不重试”画等号。实施前先核对既有逻辑调用、物理 transport 和 Supervisor 扣预算方式，明确持久化计数与门禁口径，并与 ADR/组件协议同步。不要为了集成方便移除既有行为、遗漏物理调用或无声扩大上限；如发现文档与实现冲突，记录具体差异后处理。
