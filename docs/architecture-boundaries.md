# 架构边界与模块规则

## 产品与架构边界

- 当前产品只面向个人用户。一个 Project 只有一个 `owner_user_id`，不得预建 Workspace、Membership、成员邀请、团队角色、评论、Review Task、共享项目或团队预算。
- 仓库采用前后端同仓、运行时分离的模块化单体。当前实现包含 PostgreSQL 数据底座、目标无关的 CaseFile v1 唯一机器契约、真实 SourceRecord → Brief 审阅/原子确认 → 单 Agent → Validator → Snapshot 纵向切片，以及 `apps/web` 中 React/Next.js 实现的唯一产品壳与"数字档案纸"界面。建案、Brief、工作台不再维护演示/真实两份实现，`/demo`、`/demo/brief`、`/demo/workbench` 仅为真实路由兼容跳转；Prototype Store 只服务尚未接入后端的推理和质量实验页。Validator 当前覆盖结构、引用和确定性语义门禁，Simulation、Compiler 和任何 Target Adapter 后端仍未实现。
- 数据库使用 PostgreSQL 18、SQLAlchemy 2、Alembic 和 psycopg。
- 所有关系表主键使用 `BIGINT GENERATED BY DEFAULT AS IDENTITY`；禁止 UUID 主键和额外 `public_id`。只有 CaseFile 契约对象保留稳定字符串 `object_id`。
- CaseFile 当前态采用轻量对象注册表、规范化专用内容表和统一多值引用边；完整 Draft Snapshot 与 Canon 使用不可变 JSONB。JSONB 只承载开放叶子结构，不得承载身份、状态、版本或关系。本轮不加入全文索引、全表 GIN、PostGIS 或 pgvector。
- `docs/` 是本地产品与架构输入，Git 默认忽略；运行时代码不得依赖其中的文件存在。数据库代码侧的受跟踪说明位于 `backend/migrations/README.md`。
- `var/` 只存本机运行数据，禁止提交。

## 根目录文件说明

| 路径 | 职责 |
|---|---|
| `.gitattributes` | 固定文本换行和仓库生成物属性。 |
| `.gitignore` | 排除 `docs/`、`var/`、密钥、依赖、虚拟环境和缓存。 |
| `.env.example` | 本地开发与可丢弃测试 PostgreSQL 的公开变量名和安全默认值；不得放真实凭证。 |
| `README.md` | 数据库底座简介、环境准备、启动、迁移与检查入口。 |
| `AGENTS.md` | Coding Agent 入口，包含项目定位、常用命令和编码指南导航。 |
| `AGENT.md` | 原代码职责地图（正在迁移至 `docs/` 目录下的分主题文档）。 |
| `package.json` | monorepo 的前端与跨语言契约统一命令和开发工具依赖；不放后端业务运行依赖。 |
| `pnpm-workspace.yaml` | pnpm workspace 范围、依赖构建白名单和跨包兼容性 override。 |
| `pnpm-lock.yaml` | JavaScript/TypeScript 工具与 workspace 依赖的可复现锁文件。 |
| `infra/compose/docker-compose.yml` | 仅绑定回环地址的 PostgreSQL 18 开发库与独立 `_test` 测试库。 |
| `scripts/bootstrap.ps1` | 幂等准备本地 `.env` 与加密主密钥、两个 PostgreSQL 容器、开发库迁移、38 表/head 验证，以及可选开发用户种子。 |
| `scripts/dev.ps1` | 从仓库根目录启动 `apps/web` 本地开发服务器；API 与 Worker 仍按各自入口启动。 |
| `scripts/benchmark.ps1` | `brief_to_draft` Benchmark CLI 入口，支持 fake/openai Provider、重复运行和 JSON 报告。 |
| `scripts/generate-contracts.ps1` | 从根目录跨语言 Schema 生成 Python/TypeScript 契约包。 |
| `scripts/check-contracts.ps1` | 检查根目录跨语言契约生成漂移和 Fixture 往返。 |
| `scripts/check.ps1` | 统一执行依赖、迁移命名、编译、Ruff、mypy、Alembic 与 pytest；破坏性测试前校验 `_test` 库名。 |
| `scripts/check-migration-names.ps1` | 检查迁移文件真实时间戳、命名、revision 唯一性和单链关系。 |
| `scripts/new-migration.ps1` | 按 Asia/Shanghai 当前时间创建带大写 `V` 前缀的 Alembic 迁移。 |

## 模块依赖方向

- `backend/src/casefile/core` 是纯领域与应用层，不得 import FastAPI、SQLAlchemy、Provider SDK 或具体文件系统实现。
- `backend/src/casefile/api` 和 `backend/src/casefile/worker` 是两个运行入口；可组合 core 与外层 adapter，但互不调用对方入口。
- `contracts/schemas` 是跨语言机器契约的唯一源头；`contracts/generated` 只存生成物，禁止手改。
- 跨领域调用必须经过 `core` 中公开的应用端口，不能跨模块直接查询数据表。API route 只完成协议转换、依赖解析和调用应用服务，不写业务规则。
- 骨架目录中的 `.gitkeep` 只用于追踪尚未实现的模块边界。首次加入真实文件时必须删除同目录 `.gitkeep`，并在本文登记真实职责。
