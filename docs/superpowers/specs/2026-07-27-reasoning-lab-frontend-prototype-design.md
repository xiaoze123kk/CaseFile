# 推理实验室前端原型设计

## 1. 文档状态

- 日期：2026-07-27
- 状态：已完成头脑风暴，等待用户审阅
- 实施范围：仅 `apps/web` 本地可点击前端原型
- 技术基线：Next.js 16、React 19、TypeScript、`@xyflow/react`、`@dagrejs/dagre`

本轮不实现后端 Agent、数据库写入、真实 Validator、任务队列、SSE、API 或模型 Provider。完整产品链路只作为前端状态命名和未来接口边界的参考，不进入当前实施计划。

## 2. 背景与目标

当前全站侧栏已经保留“推理实验室”规划入口，CaseFile 数据模型也具备 Hypothesis、Reasoning Path、Reasoning Node、Reasoning Edge、Resolution 和 Constraint 等推理概念。现有前端原型使用 React/Next.js、`useReducer` 和 LocalStorage 演示建案、Brief、工作台、Agent 变更审阅、验证与编译门禁。

本轮目标是在既有“数字档案纸”视觉体系内，把“推理实验室”实现为一个本地可点击原型：

1. 用户手动触发 Agent 对整个 CaseFile Draft 的模拟分析。
2. 原型展示主路径、备选路径、已排除路径和待求证缺口。
3. 用户先看整卷推理总览，再进入单条路径画布。
4. 画布展示完整、可追溯的“来源 → 主张 → 假设 → 结论”结构。
5. Agent 结果先进入候选态，用户在画布与右侧审阅栏中逐项批准。
6. 批准后由本地状态模拟 Draft Revision 变化和验证结果过期。

## 3. 已确认的产品决策

### 3.1 使用视角

推理实验室首先服务于作者全知视角。它展示真实因果、证据、主张、假设、反证和结论，不承担玩家阶段可见信息模拟；玩家视角继续归属于独立的“玩家模拟器”。

### 3.2 Agent 触发方式

- 进入 `/reasoning` 不自动运行 Agent。
- 用户必须主动点击“生成整卷推理图”。
- CaseFile Draft 更新后只显示 Revision 过期提示，不自动重画。
- 用户可以再次手动生成。

### 3.3 生成模式

原型提供两种模式：

- **整理现有结构**：组织已有对象和关系，不提出新的事实、主张或假设正文。
- **探索推理**：允许生成候选主张、假设、反证和关系；所有新增内容明确标记为 AI 推断。

两种模式都只产生候选结果，不直接修改本地 Draft 状态。

### 3.4 分析范围

每次生成模拟读取整个当前 Draft，而不是要求用户先选择问题。Agent 自动识别核心问题，并一次生成：

- 主推理路径；
- 备选推理路径；
- 已排除路径及排除理由；
- 跨路径共用对象；
- 信息不足形成的待求证缺口。

### 3.5 画布组织

- 入口先展示“推理总览”，包括核心问题、路径健康度、缺口、冲突和来源覆盖。
- 用户点击路径后进入单路径画布。
- 主张、假设和结论构成常显推理主干。
- 证据、事件、人物和地点默认聚合为可展开来源包。
- 来源包可在画布内展开，也可跳回 CaseFile 工作台对应对象。

### 3.6 编辑边界

采用混合编辑：

- 画布允许新增或删除假设、调整语义连线、编辑结论槽位和重新布局。
- 证据、事件、人物、地点等源对象正文不在实验室重复编辑，统一跳回工作台。
- 画布布局状态不得成为第二套 CaseFile 事实源。

### 3.7 候选审阅

采用“画布 + 右侧审阅栏”：

- 候选节点使用候选色和虚线边框。
- 候选连线使用虚线。
- 右侧栏显示类型、来源对象、结构化理由、支持与反驳数量、置信度。
- 用户可逐项接受、拒绝或批量批准所选项。
- 待求证节点不得伪装为事实。

## 4. 当前原型范围

### 4.1 本轮包含

- 新增 `/reasoning` 路由。
- 将侧栏“推理实验室”从规划按钮改为可用链接。
- 新增空态、模拟生成进度、推理总览、路径画布、来源包和候选审阅。
- 使用本地固定样例生成主路径、备选路径、排除路径和缺口。
- 模拟 Agent 任务的开始、进度、取消、完成和失败。
- 模拟候选逐项选择、批准、Revision 变化和验证结果过期。
- 模拟候选基线落后于当前 Draft 时禁止批准。
- 通过 LocalStorage 保留原型状态。
- 提供本地重置能力，并继续复用全站现有重置入口。
- 补充前端状态、组件和浏览器闭环测试。

### 4.2 本轮不包含

- 不调用真实模型。
- 不新增后端路由、服务、Worker、数据库表或迁移。
- 不读取真实 FastAPI CaseFile API。
- 不定义生产级 Agent Runtime、任务租约、重试或用量计费。
- 不实现真实语义 Validator。
- 不实现多人协作、评论、Review Task 或共享画布。
- 不实现玩家视角切换。
- 不实现方案三中的 Agent 实时操作画布动画。
- 不为超大规模图引入 WebGL、虚拟化或分布式布局。

## 5. 页面与组件设计

### 5.1 路由壳

`apps/web/app/reasoning/page.tsx` 只装配推理实验室 Feature Screen，不承载业务交互或原型状态迁移。

### 5.2 未生成状态

页面展示：

- 当前 Draft Revision；
- “整理现有结构”和“探索推理”模式；
- 预计读取的人物、地点、事件、信息、证据、主张和约束数量；
- “生成整卷推理图”按钮；
- “不会自动运行、不会直接写入 Draft”的明确说明。

用户未触发前不显示伪造的推理结果。

### 5.3 模拟生成状态

点击生成后，前端定时推进以下阶段：

1. 固定当前 Draft Revision；
2. 建立整卷对象索引；
3. 识别核心问题与多条路径；
4. 检查来源、反证和缺口；
5. 生成画布布局；
6. 进入候选审阅。

用户可以取消任务。取消后保留一条本地任务记录，但不产生候选变更。

### 5.4 推理总览

总览展示：

- 核心问题数；
- 路径数；
- 待求证缺口数；
- 约束冲突数；
- 来源覆盖率；
- 主路径、备选路径和已排除路径卡片；
- 跨路径共用对象；
- 尚未归类的发现。

点击任一路径卡片进入对应画布。

### 5.5 单路径画布

画布采用三栏结构：

- 左侧：路径导航，包括主路径、备选路径和已排除路径；
- 中间：React Flow 节点画布；
- 右侧：普通检查器或候选审阅栏。

画布工具栏提供：

- 返回总览；
- 自动布局；
- 适应画布；
- 新增假设；
- 新增语义连线；
- 来源包展开或折叠；
- 路径筛选。

### 5.6 自定义节点

至少包含以下节点视觉：

- 来源包；
- 主张；
- 假设；
- 结论；
- 待求证缺口。

节点还区分：

- 已存在；
- AI 候选；
- 人工确认；
- 已排除；
- 冲突或低置信。

状态必须同时使用文本、图形或线型表达，不得只依赖颜色。

### 5.7 候选审阅栏

审阅栏展示当前候选的：

- 变更类型；
- 节点或连线摘要；
- 来源对象 ID；
- 结构化理由；
- 支持与反驳数量；
- 置信度；
- 接受、拒绝和批量批准操作。

批准所选项后：

- 只把选中候选切换为已确认态；
- 本地 Draft Revision 增加一次；
- 现有验证结果标记为过期；
- 任务历史记录 baseRevision 和 outcomeRevision；
- 未选候选保持候选态或按用户操作拒绝。

## 6. 画布技术方案

采用：

- `@xyflow/react`：节点、边、平移、缩放、选择、拖拽、连线、MiniMap 和视口控制；
- `@dagrejs/dagre`：单条路径的左到右自动布局。

选择原因：

1. 当前仓库是 React 19，`@xyflow/react` 当前 peer dependency 支持 React 17 及以上。
2. React Flow 自带画布交互和键盘基础能力，避免自行实现缩放、框选和连线。
3. 自定义节点使用普通 React DOM，能够复用现有“数字档案纸”设计令牌。
4. Dagre 适合首版有方向的单路径推理图；总览采用卡片布局，不要求 Dagre 处理跨路径复合子图。
5. 语义数据与 React Flow 的坐标、视口和选择状态保持分离。

首版不使用 React Flow Pro，也不引入 ELK、Konva 或 WebGL。

参考：

- React Flow：https://reactflow.dev/
- 自定义节点：https://reactflow.dev/learn/customization/custom-nodes
- React Flow 布局说明：https://reactflow.dev/learn/layouting/layouting

## 7. 本地原型状态

在现有 `PrototypeState` 中新增清晰独立的 `reasoning` 域，避免把推理画布状态塞入事件工作台组件。

建议状态至少包含：

- `status`：`idle | running | review | ready | stale | failed | cancelled`；
- `mode`：`organize | explore`；
- `baseRevision`；
- `outcomeRevision`；
- `progress` 与当前阶段；
- 核心问题与路径摘要；
- 推理节点和语义边；
- 候选变更与选择状态；
- 每条路径的坐标和折叠状态；
- 当前路径、当前节点和当前候选；
- 最近一次生成任务记录；
- 模拟错误类型。

语义节点、语义边和画布投影使用不同类型。重新布局只更新投影坐标，不更新节点正文、来源、关系类型或确认状态。

现有 Agent 线程的 Revision、进度和结果命名可以复用，但推理实验室不得直接依赖 `features/workbench/agent-collaboration-drawer.tsx`。跨页面真正共用的纯类型或展示逻辑，应放入明确的共享边界；首版不做无需求的通用 Agent 框架重构。

新增 `reasoning` 域时同步提升 LocalStorage 的 `storageVersion`，并为旧版原型状态补入默认推理空态，保留已有 Brief、事件、验证和 Agent 线程数据；不得因为新增模块无条件清空用户现有本地原型。

## 8. 模拟数据与状态转换

原型样例围绕现有工作台中的权限记录、状态回滚、第五人和信息泄露问题构建。

“整理现有结构”返回固定的已有主张、假设和路径组合；“探索推理”额外产生候选假设、候选关系和待求证缺口。所有结果由本地 Fixture 或纯函数生成，不把自由文本随机化伪装成真实 Agent。

主要状态转换：

- `idle → running`：用户手动生成；
- `running → cancelled`：用户取消；
- `running → review`：模拟阶段完成；
- `review → ready`：批准所选候选；
- `review → stale`：baseRevision 落后于当前 Draft；
- `failed → running`：用户显式重试；
- 任意状态 → `idle`：重置原型。

## 9. 原型异常场景

前端需要可演示以下失败状态：

- 生成任务被用户取消；
- 本地模拟生成失败；
- 候选存在待求证缺口；
- 画布布局失败时降级为基础网格或列表；
- 工作台 Revision 已变化，候选禁止批准；
- 没有选中任何候选时禁止批量批准。

这些状态只影响本地原型，不暗示后端已经具备相同能力。

## 10. 可访问性与响应式

- 节点和边必须具有可读名称。
- 候选、确认、排除和缺口状态不能只用颜色表达。
- 键盘可以聚焦节点、打开检查器、执行审阅和返回总览。
- 画布外保留文本化路径导航，避免所有信息只存在于空间位置。
- 窄屏优先保留总览和只读浏览；编辑时右侧审阅栏切换为抽屉。
- 所有按钮使用明确中文动作，不使用仅图标且无 `aria-label` 的控制。

## 12. 测试与验收

### 12.1 纯函数与 Reducer

- 进入页面不会自动改变状态。
- 两种模式生成不同的固定候选集合。
- 同一 Fixture 产生稳定路径、节点和边顺序。
- 重新布局不改变语义节点和边。
- 取消任务不产生候选变更。
- 只批准选中候选。
- 批准后 Revision 只增加一次。
- baseRevision 过期时禁止批准。
- 重置后恢复初始状态。

### 12.2 组件测试

- 空态显示手动生成入口。
- 生成状态显示阶段与取消操作。
- 总览正确展示主、备选、排除路径和缺口。
- 来源包能够展开和折叠。
- 路径切换更新画布。
- 候选节点、候选边和审阅栏保持选择同步。
- 无选择、过期或失败状态下按钮禁用正确。

### 12.3 前端门禁

从 `apps/web` 执行：

- `pnpm lint`
- `pnpm typecheck`
- `pnpm test`
- `pnpm build`

### 12.4 浏览器闭环

至少验证：

1. 打开推理实验室时不自动生成；
2. 选择“探索推理”并手动生成；
3. 观察完整模拟进度；
4. 从总览进入主路径；
5. 展开来源包；
6. 从来源对象跳转到工作台并保留对象定位上下文；
7. 选择部分候选并批准；
8. 确认 Revision 更新且验证结果过期；
9. 模拟 Revision 过期并确认批准被阻止；
10. 刷新页面后 LocalStorage 状态仍在；
11. 使用旧版 LocalStorage 状态启动时保留已有原型数据并补入推理空态；
12. 重置原型后恢复初始空态。

## 13. 验收标准

完成必须同时满足：

- “推理实验室”侧栏入口可用。
- 页面保持现有 CaseFile 视觉体系。
- 首次进入不自动运行。
- 用户一次手动操作可以看到整卷模拟推理结果。
- 总览、主路径、备选路径、排除路径和缺口可浏览。
- 主干常显，来源包可展开。
- 画布支持平移、缩放、节点拖拽和自动布局。
- 候选内容在画布和审阅栏中同步。
- 未批准候选不会改变本地 Draft Revision。
- 批准所选后仅选中候选转为已确认态，Revision 增加一次。
- 取消、失败、过期和布局降级状态可演示。
- LocalStorage、重置、测试、构建和浏览器闭环均通过。

## 14. 后续增强

方案三“Agent 持续操作画布”作为后续增强：在真实任务流稳定后，可以把结构化阶段结果逐步投影为节点和连线动画，让用户实时观看 Agent 如何组织图形。该增强不得改变当前语义数据与视图数据分离、人工批准和 Revision 门禁。
