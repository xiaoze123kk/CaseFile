# N4.4 Scene Execution Compiler

N4.4 将 N4.3 已规范化的 `compiler.novel-plan.v1` 与匹配 NarrativeIR 冻结为 `compiler.scene-compiler-input.v1`，由未来模型只填充 Scene 内来源支持的结构化 Beat，再由服务器规范化为不含正文的 `compiler.scene-plan.v1`。本阶段回答“故事如何按场景发生”，不重新规划主线，不读取 Planner Prompt/repair/benchmark 私有实现，也不承担 N4.5 的文风、对白或小说正文生成。

当前先落地 `Narrative Execution Benchmark v1`，不接生产 Provider、不运行 live baseline、不激活 Worker 模型路径，也不预设晋级阈值。既有纯确定性展开继续作为 reference/baseline helper，不代表 N4.4 模型能力。

## 契约命名与阶段边界

N4.2 已冻结 `NarrativeIR` 为 CaseFile Snapshot 的无损语义投影，因此 N4.4 不复用或重定义该名称。N4.4 输出使用 N4.0 已预留的 `scene_plan` Artifact kind，公开类型为 `ScenePlanIR`：

```text
CaseFile Snapshot
  → NarrativeIR          (N4.2，无损事实 IR)
  → NovelPlanIR          (N4.3，故事规划)
  → ScenePlanIR          (N4.4，执行计划)
  → prose/draft renderer (N4.5，正文)
```

Scene Compiler 消费完整、可独立序列化的 `NovelPlanIR + NarrativeIR` 冻结 Bundle，不 import Story Planner、Provider、Prompt、repair 或 benchmark 代码。模型 Candidate 不拥有 Chapter/Scene 身份、顺序、目的、POV、依赖、稳定 ID、哈希、索引或来源证明。现有 `CompileArtifact + AgentStepRun + TaskRun` 分别是产物、组件审计与执行终态的唯一权威，不额外引入重复的通用 `CompilationResult[T]`。

## ScenePlanIR v1

`ScenePlanCandidate` 只按既有 Scene 输出有序 Beat directive、kind、participant/location/time/basis refs 与 Event/Exposure/Resolution 动作。服务器校验所有引用均存在且属于该 Scene 的来源白名单，完整覆盖计划动作后，`ScenePlanIR` 保留 NovelPlan 身份与顺序并确定性派生：

- `beat_{scene_id}_{ordinal}` Beat ID 与内容寻址的稳定 Edge ID；
- Chapter → Scene、Scene → Beat、Scene prerequisite 的显式图边；
- 每个 Scene 的 objective、POV、参与者、地点、故事时间与来源证明；
- 每个 Scene 前后的读者 Exposure 状态、本场允许揭露与未来禁止揭露 key；
- Event、Exposure、Resolution 与无显式动作 Scene 的最小 transition Beat；
- chapter/scene/beat、dependency、Exposure、Resolution 派生索引与计数。

同一规范 NovelPlan 必须产生完全相同的 JSON 与 RFC 8785 SHA-256。Beat directive 是供后续 Renderer 消费和调试的结构化执行指令，不是小说正文。

## Graph 与 Linter

`NarrativeExecutionGraph` 在领域层内部封装 `networkx.MultiDiGraph`，公开契约只保存普通节点 ID 与 typed edge。当前提供 ancestors、descendants、affected nodes 与 dependency cycle 查询；NetworkX 类型不会进入 Pydantic/JSON Schema。

确定性 linter 复验 Input/Candidate 双哈希、NovelPlan 索引与依赖 DAG、Scene/Beat 覆盖、引用接地、揭露、时间、Resolution 和 provenance；规范化后生成语义签名，忽略 directive 措辞但绑定全部结构语义。本 Benchmark 里程碑不新增 Worker 模型调用或生产激活。

## Benchmark v1

Suite 冻结 8 个能力族与 basic/decoy/dense 三类变体，共 24 Task：Scene decomposition、Event grounding、Reveal control、Temporal grounding、Dependency transfer、Resolution execution、Scene grounding 与 Provenance coverage。每题含完整冻结输入、known-good Reference 与可审计 input evidence paths；每个能力族另有一个结构不同但合法的 Alternative，grader 不做 Reference JSON 精确匹配。

G0 检查输入绑定与 Candidate 契约，G1 执行零容忍确定性 conformance，G2 按 Outcome coverage 评分，G3 只冻结五维 Writer executability rubric，G4 只生成结构语义签名。Capability reference replay、Regression alternatives 与 Safety mutations 分开报告；任何报告均固定 `qualification.status=uncalibrated`、`qualified=false`，直到后续独立的正式 24×3 Pro baseline 完成并前瞻冻结门槛。

## 明确延期

- Character Knowledge、location/resource state、setup/payoff 与 semantic causality 不能从当前 NovelPlan 的 ID/ref-only 契约可靠推断；本版不编造这些状态。后续必须先增加来源支持的 typed obligation/input projection，再扩展 State Engine。
- 本版用确定性规则与 NetworkX 完成结构执行和验证，不引入 `z3-solver`。只有 Benchmark 证明存在大量局部规则无法处理的联合可满足性问题，或需要自动搜索合法 Scene 排列时，才评估独立 Solver backend。
- N4.4 不写正文，不评估文学性，不增加 Writer/Editor/Rewrite Agent。

## ScenePlanIR v2 影子链路

在 v1 确定性基线和独立 Benchmark 之上，N4.4 新增未默认激活的
`compiler.scene-compiler.shadow.v1`：完整审计输入绑定 NovelPlan、NarrativeIR、Exposure
与 Profile，Provider 只接收章内最多八场的最小 ModelView。模型只填写 goal、conflict、
outcome 与结构化 Beat；服务端 State Engine 重新分配 ID、重建 Exposure、应用来源支持的
Knowledge/Location 增量，并规范化 causal edge 与 setup/payoff。

影子链路产出 `compiler.scene-plan.v2`，历史 `compiler.scene-plan.v1` 继续可读、可重放。
Application Service 默认仍创建现有 Constraint-First TaskRun；只有内部显式
`scene_compiler_shadow` 运行会调用 Scene Fill。正式默认切换必须等待独立 Benchmark
完成资格校准和晋级，不以本次组件测试代替能力证据。
