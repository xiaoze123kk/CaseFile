# N4.4 Typed Inbound State 与 Prompt v3 诊断报告

## 结论

本轮继续修复 N4.4 ScenePlan 低成功率，但没有启动新的完整 24×3 正式复评。

第一项单变量修复把跨 batch 的不透明 proposal hash 链升级为 typed inbound state：下一批
显式接收当前角色知识、known fact 的知识操作白名单、开放 setup 与全部已用 setup key。
Prompt v2、ModelView projection v3、Suite、Validator、模型与预算保持不变。原三题×3 的
`deepseek-v4-pro` 诊断从上一轮 6/9 提高为 7/9；knowledge-state 失败由 2 次降到 0，
`scene_decomposition__decoy` 从 0/3 提高为 3/3，infra=0。剩余两次失败均为新的
`compiler_scene_fill_obligation_kind_mismatch`。

第二项单变量只升级 Prompt 为 v3，明确 obligation.kind 与 Beat.kind 必须完全一致，禁止
同一 Beat 合并不同 kind 的 obligation。对唯一失败任务 `reveal_control__decoy` 的三次
定向复评为 3/3、infra=0、kind mismatch=0。

两轮诊断分别证明目标失败族已闭合，但都不是完整 24×3，且当前实现尚未固定为 clean Git
revision。因此资格保持 `uncalibrated / qualified=false`，不得把定向结果拼接成 9/9 或正式
晋级证据。

## 实现边界

- 新契约：`compiler.scene-compiler-inbound-state.v1`
- Pipeline：`compiler.scene-compiler.shadow.v2`
- ModelView：`compiler.scene-compiler-model-view-projection.v3`，未修改
- Prompt v2：保留不可变历史版本
- Prompt v3：只新增 obligation/Beat kind 对齐规则
- Validator、SemanticFill Schema、State Engine 最终完整重放与 G0–G4 评分未放宽

运行时在每个成功 batch 后立即应用知识与 setup/payoff 前缀状态。下一批的 input hash 同时
绑定完整内部状态 hash 和 batch 可见 typed projection；exact-hash 恢复仍只接受完全一致的
输入。known fact 的允许操作为 `learn/believe/correct`，不允许 `misbelieve`，并与最终 State
Engine 共享同一操作规则。
