# N4.4 Setup/Payoff Prompt v4 诊断报告

## 结论

本轮以 `scene-compiler-semantic-fill-v3` 的完整 24×3 正式基线为起点，只升级
Scene Fill Prompt 到 v4。Suite、ModelView projection v3、typed inbound state、
SemanticFill Schema、Validator、State Engine、模型、预算与 3-trial 参数均未修改。

Prompt v4 把 setup/payoff 明确为默认空的可选成对标记：只有同一 batch 内较早 Beat 创建、
严格后续 Beat 兑现时才允许新 setup；禁止跨 batch 延后。若存在
`inbound_state.open_setups`，每个 key 都是当前 batch 必须恰好兑现一次的显式 payoff
义务。最终 State Engine 的 `compiler_scene_setup_unpaid` 规则没有放宽。

对上一轮发生 `setup_unpaid` 的全部 7 个 Task 执行全新 `deepseek-v4-pro` 3-trial 开发诊断，
结果为 21/21、7/7 Task 三次全过、infra=0，`setup_unpaid` 与其他失败族均为 0。该结果证明
Prompt v4 值得进入完整正式复评，但任务选择不是完整 24 Task，资格仍保持
`uncalibrated / qualified=false`，不得与上一轮正式结果拼接为晋级证据。
