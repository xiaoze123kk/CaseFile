# N4.3 Story Planner release evidence

N4.3 在 NarrativeIR 后加入可选、显式选择的 Story Planner。无 Provider 的 CompileRun 保持 N4.2 行为；有 Provider 的运行冻结 provider/model/config/prompt/budget，允许一次初始调用与最多三次结构修复，语义错误不修复，并持久化规范 `compiler.novel_plan` Artifact。

确定性门禁覆盖契约生成、PlannerInput/hash、引用与 provenance、Exposure/Resolution/时序/DAG/Profile、canonicalization、Prompt inventory、结构修复上限、Benchmark contract、原子 checkpoint resume，以及六类零容忍 Safety mutation。Artifact 按完整 component fingerprint 复用且 Provider 调用数为零；Worker crash 后可重放已成功持久化的输出。

Capability Suite 冻结 24 个 Task，覆盖八项主要能力和 basic/decoy/dense 变体。Reference Solution 通过生产 Validator，但不是唯一正确场景编排；G3 只提供软诊断。

Fake 结果不冒充正式基线。CLI 对 live Capability 强制每 Task 三次 Trial，并要求 Planner 与质量 Grader 都显式使用 Pro 模型 ID。正式报告必须记录精确 provider/model 和全部 fingerprint，之后才能单独冻结发布阈值。

## 2026-08-25 Resolution coverage repair

旧 `story-planner-v2` 正式基线中，72 条 Trial 有 59 条因模型未完整覆盖全部 `resolution_spec` 而被生产 Validator 拒绝，G2 仅 10/72（13.89%）。保持 Suite、Validator、Grader、Provider、模型与调用预算不变，只将 Prompt 提升到 `story-planner-v3`，明确每个 Resolution 必须恰好一次进入 `resolve` 或 `intentionally_unresolved` 终态。

新的 `deepseek-v4-pro` 24×3 正式基线 fingerprint 为 `6830d9a49df5431117043b93f88063ae66cd960ff82d8deddde5427a6323631f`：Resolution 漏覆盖 0，语义合法 67/72（93.06%），G2 40/72（55.56%），18/24 Task 达到 pass@3，10/24 Task 三次全过，基础设施失败率与 unsafe trial rate 均为 0。报告 `status=passed` 只表示现有 Safety/Infrastructure gates 通过；Capability 尚未冻结发布阈值，不等同于 release ready。

后续 `story-planner-v4` 单变量实验加入更宽泛的规划清单，但结果回退到语义合法 63/72（87.50%）、G2 39/72（54.17%）、pass@3 17/24，因此未采用，运行时默认保持 v3。对应本地报告分别为 `backend/var/benchmark/novel-plan-capability-pro-v3.json` 与 `backend/var/benchmark/novel-plan-capability-pro-v4.json`。

## 2026-08-25 Benchmark contract audit and PlannerInput v2

Capability Suite v3 保留原 24 Task/Reference/Outcome 语义，为每项 G2 invariant 增加 `expectation_class`、Planner 可见 `input_evidence_paths`，并让 runtime-hard invariant 显式绑定生产 Validator reason code。每个 Task 同时冻结 v1 与 v2 PlannerInput；正式运行只接受 provider=`deepseek`、Planner/质量 Grader model=`deepseek-v4-pro` 和每 Task 三次 Trial，不再以名称包含 `pro` 代替精确身份。

新增 `compiler.story-planner-input.v2`，在完整 NarrativeIR/Exposure/Profile 之外确定性投影 PlannerView。Structure、Exposure、Resolution 与可比较时间锚点属于硬约束；因果边、Knowledge State 和原始作者 note 只作为上下文，不从自然语言臆造硬规则。Validator 会从冻结输入独立重建 PlannerView，指纹额外绑定输入 schema 与 view hash。

当前生产 Worker 和默认 `story-planner-v3` 仍使用 PlannerInput v1。只有 audited v3 Suite 的完整 24×3 Pro 候选达到冻结 promotion gate 后，才允许单独提交激活；本次契约/评测基础设施本身不等同于 Capability promotion 或 N4.3 release ready。

在 ModelView v3 上继续运行精确 presentation-mode normalization。完整 24×3 报告 fingerprint 为 `8ede2941b8d9757a01b426f811edda0eeac5ce3564d686e0d89b1451ef60b6ba`：同轮原始 semantic-valid 62/72，规范化后 67/72，G2 60/72，pass@3 23/24，all-three 15/24，unsafe 与 infrastructure failure 均为 0。5 次规范化全部把与事实时间矛盾的 `flashback` 改为 `linear`，同时全部引入 `presentation_mode_present` G2 失败；因此该实验不得晋级。Benchmark promotion gate 必须额外要求任何 normalization/semantic repair 不引入新的 G2 failure，不能只凭 semantic-valid 达到 67/72 判定成功。
