## 结论

`state_seed → object_catalog` 引用闭包缺陷已经修复：正式 `deepseek-v4-pro`
24×3 中 `compiler_scene_fill_reference_invalid` 从 42 次降为 0。端到端通过率从

本轮结果固定为 `baseline_observed / qualified=false`。没有运行 G3，没有修改 Prompt、
Validator、Suite、预算或模型，也没有对基础设施/能力失败做选择性补跑。

## 根因对照

v2.1 的 42 次 reference failure 全部发生在第二 batch。旧 projection 只按顶层
subject/event 选择状态行，却把 knowledge/event 内嵌引用暴露给 Provider，同时没有把这些
引用加入 `object_catalog`。projection v2 为可见状态引用补齐对象目录，并在缺失 NarrativeIR
对象时于 Provider 前失败关闭。

正式结果中的 `reference_invalid=0` 证明该 P0 已闭环。通过数只增加 8 而不是 42，说明旧
reason code 曾遮蔽后续门禁；闭包修复后，主要剩余问题显现为 Scene 允许 basis 与模型选择
不一致的 provenance 越权。本轮按单变量规则不继续修复该新失败族。

Basic 固定为单 batch，而 Decoy/Dense 固定为双 batch，因此 variant 结果仍与 batch 数量
混杂。v2.2 可以证明端到端闭包修复和当前通过率，但不能把 Decoy/Dense 差异解释为纯模型
推理能力差异。
